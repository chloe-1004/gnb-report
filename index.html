03-B · 닫기를 왼쪽에 유지하면 어떻게 되나?
케이스 A
닫기만 있는 화면
✕ 닫기 타이틀
⚠ 뒤로가기 버튼 추가 불가
나중에 이 화면에 서브 뎁스가 생기면 왼쪽이 이미 닫기에 점유돼 있어서 뒤로가기 둘 자리가 없음. 강제로 같은 줄에 2개를 두거나, 다시 위치를 바꿔야 함.
케이스 B
뒤로가기 + 닫기 동시
← 뒤로 타이틀 ✕ 닫기
⚠ 여기서만 닫기가 오른쪽이 됨
왼쪽에 닫기 원칙을 세워도 뒤로가기가 함께 있을 땐 닫기가 오른쪽으로 밀려남. 원칙 자체가 "왼쪽"을 보장할 수 없는 구조.
케이스 C
신고하기 플로우
✕ 닫기 신고하기 2단계  
⚠ 닫기 = 플로우 처음으로? 나가기?
신고 2단계에서 왼쪽 닫기를 누르면 "신고 전체 취소"인지 "1단계로 돌아가기"인지 불명확. 뒤로가기와 닫기가 분리되지 않으면 의미 혼란.
결론: 닫기를 왼쪽에 고정하려 해도 뒤로가기가 생기는 순간 원칙이 깨짐. "왼쪽 닫기"는 확장성 없는 원칙이고, 케이스 B·C에서 결국 오른쪽 닫기로 수렴됨.
